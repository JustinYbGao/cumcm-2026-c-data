## 2. 你现在先做的三件事

1. **把数据任务发给负责数据的朋友。** 使用《C题-数据处理任务交接.md》，要求先交问题1的144时段数据，不等全年处理结束。
2. **组织队内确认关键口径。** 逐项填写下面的口径表；无法确定的保留两种情景，不默默选一个。

在等待数据朋友交付期间，建模人员可整理公式、写小例子与审计函数，论文人员可搭结构并建立资料记录。正式求解依赖的数据未验收前，不把试跑结果当作结论。

## 9. 阶段六：基线全部跑通后，再做创新

**负责人建议：你统筹实验取舍，建模与代码实现，论文人员保存证据。**

### 创新候选A：连续缺口风险与储能余量

- [ ] 用真实时间顺序预测产生的残差构造累计缺口风险。
- [ ] 比较无余量、固定余量、分位风险相关余量。
- [ ] 检查每个时段SOC与功率，不把累计分位当成全窗口安全保证。
- [ ] 报告总费用、紧急购电、连续缺口和失效情景。
- [ ] 若效果不稳或不省钱，删去该模块。

### 创新候选B：更新预报的经济价值与可靠性

- [ ] 区分0点信息固定、只更新储能控制、允许付费调整购电。
- [ ] 用同一对照条件拆分信息价值与交易调整价值。
- [ ] 有足够历史证据后，才尝试收益可靠性门槛。
- [ ] 不把“优化器选择成本低的方案”本身包装为创新。
- [ ] 若额外门槛没有样本外收益，保留标准MPC。

**验收标准：** 每个保留的改进都有可复现对照；一次只改变一个关键组件；报告幅度和失败条件，不只展示最好一天。

**如果时间不足：** 优先完成四问、结果文件、审计与论文，减少创新模块，不能牺牲基础正确性。

## 11. 每次队内同步，只确认这五项

1. 本阶段交付物是否产生，放在哪里？
2. 通过了哪些检查，有没有失败或待确认项？
3. 是否改变了数据、口径、模型或执行规则？
4. 哪些下游结果因此需要重算？
5. 下一个可以独立推进的具体动作是什么？

建议每次模型或数据发生实质变化，就标记下游结果“待重算”，不要把旧费用和新图混进同一版论文。

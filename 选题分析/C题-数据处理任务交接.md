# 2026 C题：数据处理任务交接

**题目：微网与外部电网电力调控策略**

本文交给负责数据的队员，目标是将四份输入附件整理为可供“预测—调度—实际运行—结果评价”统一框架使用的数据。先完成数据结构与时间口径，不要求这一步完成最终预测模型或优化求解。

原始文件位于 `CUMCM2026Problems/C题/附件/`。另有附件5结果模板文件夹，需要检查模板结构，但不要在数据处理阶段向模板填入虚构的策略结果。

## 1. 四个附件分别是什么意思

| 附件 | 文件内容 | 数据性质 | 用在哪些问题 |
|---|---|---|---|
| 附件1.xlsx | 某一天各时段的电价、小区负载、光伏发电预测功率 | 单日基础案例；光伏是预测值 | Q1使用全部字段；Q2、Q3只使用其中电价 |
| 附件2.xlsx | 2025年全年实际小区负载、实际光伏发电功率，分别在两个工作表 | 实际发生的供需数据 | Q2、Q3、Q4 |
| 附件3.xlsx | 每天0、6、12、18点发布的未来24小时整点光伏预报 | 不同发布时间对未来的估计 | Q3、Q4 |
| 附件4.xlsx | 2025年全年各时段电价 | 实际波动电价 | Q4 |

### 1.1 附件1：单日基础案例与固定日内电价

一共144条数据，对应每天144个十分钟时段。字段为时间、电价、小区负载、光伏发电预测功率。

- 电价单位：元/kWh。
- 负载、光伏预测单位：kW，是功率，不是电量。
- Q1直接用这一天的数据制定购电和充放电策略，不需要自己训练光伏预测模型。
- Q2、Q3复用这条电价曲线，表示每天同一时段采用相同价格；不再把附件1的单日负载和光伏当作全年实际值。

### 1.2 附件2：全年真实供需

两个工作表分别为“小区负载”和“光伏发电实际功率”，均为365天×144个时段，各52560个数值，单位kW。

- 原表一行一天，第一列为日期，后面为各时段功率。
- 已经过去的实际数据可以用于分析、训练和校准。
- 当天的实际数据用于按时间推进运行，并计算储能变化、供电缺口和实际费用。
- 能从文件看到全年实际值，不代表每天0点做计划时就知道当天未来。

### 1.3 附件3：有发布时间的光伏预报

全年1460次预报，每次24个预测值，共35040个预测值，单位kW。一天4行，分别对应0、6、12、18点发布。

例如某日6点发布的“预报1小时”对应当天7点，“预报24小时”对应次日6点。

同一目标时刻会有多份预报。例如当天13点的光伏，在0点、6点、12点都可能有对应预测。它们是不同版本，不能只按目标时间去重。日期列中的空字符串表示同一天的后续预报行，需要在识别空白后向下填充日期。

### 1.4 附件4：全年波动电价

365天×144个时段，共52560个价格，单位元/kWh。

- Q4用它替换Q2、Q3采用的固定日内电价条件。
- 电价不乘时长；购电电量乘价格才得到费用。
- 题面没有明确未来实时价格提前多久可知。保留实际价格，但不要擅自将全天实际价格标为每天0点已知。

### 1.5 已完成的初检，不必误当成全部清洗完成

已检查文件与工作表结构，并对附件2—4主要数值区扫描：未发现空值、非数值或负数。负载范围约1995.7176—7978.8849 kW；实际光伏0—10216.2 kW；光伏预报0—9995.8875 kW；实际电价0.0076—1.7936元/kWh。

这些范围是观察结果，不是清洗阈值。尚需完成时间完整性、重复记录、异常跳变、时序对齐和预报误差分析。不要看到尖峰就删除。

## 2. 共同处理规则

### 2.1 原始文件保留，所有变更可追溯

原附件只读。生成新表，不覆盖原文件。修正或排除任何记录，都记录文件、工作表、原行列/时间键、原值、新值、原因。若无修正，也应说明。

建议使用Python处理，CSV作为通用交接格式，UTF-8编码；时间采用完整ISO格式。若使用Parquet，可以额外保留，但不要只交付无法方便查看的格式。

### 2.2 统一时间和区间

- 全部时间按题目本地日历处理，使用同一无时区时间口径；不要受电脑时区影响转换日期。
- 处理Excel时间对象、字符串和`0:00+1`。后者表示该日期的次日0点，即本日24点。
- 每天有144个区间，从00:00—00:10至23:50—次日00:00。
- 建议将原表的`0:10`对应区间00:00—00:10。输出同时保存区间开始、区间结束和所属业务日期。
- 对输入功率是区间平均值还是时间点值，题面未完全明确。该区间映射与转换是待与建模人员确认的口径，不要静默决定。
- 年末最后一个区间结束于2026-01-01 00:00，但仍属于2025-12-31业务日，不得丢弃。
- 日期和时段先分别解析，再组合；不要直接按时间字符串排序。

### 2.3 单位与零值

- 保留负载/PV的原始功率列，单位kW。
- 若采用区间平均功率口径，十分钟电量为 `energy_kwh = power_kw / 6`。
- 若按时间点功率曲线积分，则明确插值与边界方法，不能与区间平均法混用。
- 夜间PV零值保留，不当缺失；不对全部数据统一做标准化。
- 负载减光伏可以为负，表示富余电量。保留有符号净负载，不直接截成零。
- 内部计算保留精度，显示或提交时再按模板/题目要求处理，不在清洗阶段提前四舍五入。

### 2.4 区分三种时间

| 时间 | 含义 | 例子 |
|---|---|---|
| 目标时间/区间 | 数据描述的时刻或区间 | 当天13:00的PV，或13:00—13:10的负载 |
| 发布时间 | 一份预报何时产生 | 当天6:00发布 |
| 决策时间 | 策略何时制定 | 当天0:00日前计划或12:00调整 |

预报只有发布时间不晚于决策时间才可使用。对实际区间数据，建议以区间结束时才完整可见作为默认执行口径，并在说明中写明；若采用其他测量可用性设定，必须与运行模型保持一致。

## 3. 建议交付的基础数据表

以下字段名是建议的交接接口，可讨论后统一；不是题目原字段名。示例均为结构说明，没有虚构数值。

### 3.1 `fixed_price.csv`：固定日内价格表

来自附件1，144行。唯一键为`slot_id`。

| 字段 | 含义 |
|---|---|
| slot_id | 日内时段编号1—144 |
| start_time | 时段开始钟点 |
| end_time | 时段结束钟点，末段明确为24:00 |
| price_yuan_per_kwh | 附件1固定价格 |

### 3.2 `q1_day.csv`：问题1可直接求解的数据

来自附件1，144行。唯一键为`slot_id`。附件1没有实际日期时，使用时段索引即可，不编造来源日期。

| 字段 | 含义 |
|---|---|
| slot_id、start_time、end_time | 日内时间区间 |
| price_yuan_per_kwh | 电价 |
| load_kw | 给定负载功率 |
| pv_forecast_kw | 给定光伏预测功率 |
| load_kwh、pv_forecast_kwh | 按统一口径得到的时段电量 |
| net_load_forecast_kwh | 负载电量减PV预测电量，可为负 |

### 3.3 `actual_10min.csv`：全年真实供需与价格对齐表

附件2展开成长表，再连接附件1日内价格和附件4实际价格。预期52560行。唯一键为`interval_start`，时间对齐后连接须为一对一。

| 字段 | 含义 |
|---|---|
| date、slot_id | 所属业务日期、时段1—144 |
| interval_start、interval_end | 完整时间区间 |
| load_actual_kw、pv_actual_kw | 实际负载和实际PV功率 |
| load_actual_kwh、pv_actual_kwh | 对应电量 |
| net_load_actual_kwh | 实际负载电量减实际PV电量 |
| fixed_price_yuan_per_kwh | 按时段复制的附件1价格 |
| actual_price_yuan_per_kwh | 附件4实际价格 |

保留两个价格字段，避免替换后丢失对照。表中包含实际值是为了统一存储，不代表训练或决策程序可以无条件读取全部列和未来行。

### 3.4 `pv_forecast_hourly.csv`：原始预报版本长表

附件3展开后，预期35040行。唯一键为`issue_time + target_time`。

| 字段 | 含义 |
|---|---|
| issue_time | 完整发布时间 |
| horizon_h | 提前小时数1—24 |
| target_time | issue_time加horizon_h小时 |
| pv_forecast_kw | 该版本对目标整点的预测功率 |

不要用`target_time`单独去重。12月31日后几次预报包含2026年1月1日目标，原始长表应保留；没有对应实际数据的部分不参与误差核算，不标成零。

### 3.5 `pv_forecast_10min.csv`：调度使用的预报版本表

从小时预报转换而来。唯一键为`issue_time + interval_start`，保留每份发布时间的独立版本。

| 字段 | 含义 |
|---|---|
| issue_time | 预报发布时间 |
| interval_start、interval_end | 预测所对应的十分钟区间 |
| pv_forecast_kwh | 区间预测电量 |
| conversion_method | 采用的插值/积分方法，可在说明中统一记录 |

行数取决于保留的预测范围与边界处理。若每次发布均完整保留后24小时，每份应有144个区间，共210240行；若只保留当天剩余部分，须明确规则并单独列出预期行数，不能悄悄裁剪。

## 4. 每一问的数据处理任务和完成门槛

### 4.1 问题1：先完成，可以立即交给建模人员

**输入：附件1。**

处理步骤：

1. 解析时段并检查144个区间连续、无重复。
2. 对齐电价、负载和PV预测，保留原功率。
3. 按统一口径生成电量与有符号净负载。
4. 交付`q1_day.csv`和`fixed_price.csv`。

**验收门槛：** 时段完整、单位清楚、字段无误、转换可复算。达到后即可开始Q1优化，不用等待全年预测。

不需要：训练预测模型、标准化、拟合全年规律。

需建模人员同步确定：储能效率口径、Q1日初状态采用值与日首尾相等约束。不要在数据表中生成假定的充放电最优结果。

### 4.2 问题2：支持每天0点预测和当天实际回放

**输入：附件1电价＋附件2。**

处理步骤：

1. 负载、PV两个工作表展开，按完整时间一对一连接。
2. 附件1价格按`slot_id`映射到全年。
3. 检查全年365天，每天144个时段；生成长表。
4. 做基础探索图：负载/PV日内曲线、按星期或月份的变化、日总电量与尖峰情况。数据全貌图用于描述，不能据此用未来信息选择早期预测参数。
5. 支持按决策日期取历史数据：例如2月1日0点只取此前已完成区间的实际值。
6. 如由数据同学负责基线，先生成历史同期/同类日预测；如只负责整理，则交付历史切片与目标日真实值接口，由预测负责人生成预测。

建议基线预测交接字段：`decision_time、interval_start、interval_end、load_forecast_kwh、pv_forecast_kwh、history_end_time、method`。这属于后续生成的预测，不是原附件数据。

**验收门槛：** 给定一个待模拟日期，可获取完整的过去历史、当天144时段真实值、固定价格，并能保证过去与未来严格隔离。若预测也在本任务范围，则再要求生成144时段基线预测。

不需要：先确定最终机器学习模型或调到最好精度。

特别注意：输出策略主要覆盖2月1日至12月31日334天，但原始1月数据不能删。1月可用于启动训练；储能1月1日6000kWh如何运行到2月1日由建模人员决定，不能由数据处理程序每天重置状态。

### 4.3 问题3：预报版本管理是重点

**输入：问题2底座＋附件3。**

处理步骤：

1. 将日期列空字符串识别为缺失，再按原顺序向下填充日期。
2. 组合日期和预报时刻为`issue_time`，检查每天4个发布时间。
3. 将24个预测列展开，计算`target_time`。
4. 输出小时版本长表，检查每次发布正好24个目标点。
5. 按与建模人员确定的转换规则生成十分钟预测电量。
6. 提供按决策时间筛选预报的功能：只能取`issue_time <= decision_time`的数据；保留0点原始版本，不用新版本覆盖历史文件。

**小时到十分钟如何处理：**

- 优先保留小时原表，再生成派生十分钟表，不能只交派生表。
- 可比较分段常数基线与分段线性功率曲线积分。两者是建模口径，不能在未确认时混用。
- 对相邻预测整点之间的区间，可在同一已发布预报内插值并积分。
- 发布时间到第一个预测整点之间缺少起点值：须明确用当时可用观测、上一版可用预报或其他约定方法衔接；不得从未来实际PV取端点。
- 如果采用当时最新已完成区间的平均实际功率作为端点代理，应标明这是近似，不把它当成真实瞬时功率。
- 不在完整24小时之外擅自外推。

**验收门槛：** 给定某天0/6/12/18点，能得到当时允许使用的预报及剩余调度区间的PV预测电量；边界有规则、无未来版本穿越、旧版本仍可追溯。

不需要：先完成预报校正。可直接使用题目原预报跑通滚动调度，再决定是否校正。

如生成预报误差表：同时标明发布时间、目标时间、提前量、预测值和可比实际值。整点预测与实际十分钟数据的比较口径要统一；整点功率误差和小时电量误差是不同指标。实际尚未发生的目标不能进入当时误差校准。

### 4.4 问题4：价格对齐和信息边界

**输入：附件2、附件3、附件4。**

处理步骤：

1. 将附件4展开为完整时间索引，检查365×144个价格。
2. 与供需数据一对一连接，防止日期与时段错位。
3. 检查尖峰、低价和变化幅度，只标记、说明，不未经分析就平滑删除。
4. 保留固定价与波动实际价两列。
5. 与建模人员确认未来价格可知条件，再提供对应的价格输入。

| 信息设定 | 数据侧应提供什么 |
|---|---|
| 全天价格被假设提前已知 | 未来价格曲线；明确该设定，不能称作题面已明确事实 |
| 未来实时价格未知 | 决策时以前的价格历史、后续生成的预测价格；实际价留给执行结算 |

**验收门槛：** 任意决策时刻，可以区分决策可用价格和实际结算价格，并与供需及预测目标区间对齐。

不需要：一开始就做复杂价格预测。先把表和信息访问规则做对，再由预测负责人建立基线。

## 5. 需要确认的口径，不要自行静默处理

| 事项 | 数据处理先做什么 | 需要谁确认 |
|---|---|---|
| 功率是时间点值还是区间平均值 | 保留原功率、区间起止，派生转换注明方法 | 数据与建模人员共同确认 |
| 小时PV到十分钟的衔接/积分 | 保留原版本，提供转换方法说明 | 数据与建模人员共同确认 |
| 90%为单向还是往返效率 | 原样记录题目参数，不硬写两次损耗 | 建模人员 |
| Q2以后是否要求日首尾电量相等 | 不在原数据中强制重置储能状态 | 建模人员 |
| 1月如何衔接2月储能初值 | 保留完整1月实际数据 | 建模人员 |
| 减购、退款、违约及多次调整基准 | 保留原计划/更新版本所需时间键 | 建模人员 |
| 实时价格提前多久可知 | 实际价与预测价分字段 | 建模人员 |

前两项决定派生数据，需先统一；后五项不阻碍原表解析、长表化和质量检查。

- [ ] 零PV、有符号净负载、尖峰未被不当清除。
- [ ] 表连接一对一，无意外扩行、掉行或缺失价格。
- [ ] 十分钟预报的首小时边界处理写清楚，没有偷用未来实际值。
- [ ] 任意决策时刻均可筛选当时可用数据；训练统计没有使用未来行。
- [ ] 固定价格、实际价格、预测价格未混为同一列。
- [ ] 数据质量报告区分“检查通过”“采用假设”“尚未确认”。

## 8. 交付顺序

**先交问题1数据，不等全年工作结束。**

1. 第一批：`q1_day.csv`、`fixed_price.csv`、单位与区间口径说明，建模人员即可开始Q1。
2. 第二批：全年实际供需长表和历史切片规则，支持Q2基线。
3. 第三批：小时预报版本表、十分钟派生表及边界说明，支持Q3。
4. 第四批：波动价格连接、价格信息规则，支持Q4两分支。
5. 最后补充：完整质量报告、探索图、可复现脚本及异常说明。

数据整理阶段的成功标准是：每一条数值都知道代表什么、何时发生或发布、单位是什么、在什么决策时刻允许使用。预测模型的最终选择和调度效果比较在这个基础上继续。
